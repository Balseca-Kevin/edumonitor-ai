# Evidencia TA-04.4 · Permisos 200, 401 y 403 contra la API real

- **HU:** HU-04 · Autenticación JWT y autorización por rol y por curso
- **Fecha:** 22 oct 2026, 14:01 (-05:00)
- **Entorno:** API en `http://localhost:5000` (Development, código de `develop`), SQL Server de `moodle-lab` con los usuarios semilla
- **Datos:** doc01 tiene asignado AGIL-4B (id 1); BDD-4B (id 2) es de doc02.
- **Criterio (DADO / CUANDO / ENTONCES):** el docente A que pide un curso del docente B recibe 403; sin token recibe 401; con credenciales válidas recibe 200 con un JWT que incluye su rol y vence en el tiempo configurado.

El JWT aparece como `••••` más sus últimos 4 caracteres y la contraseña de semillas está tapada. Las pruebas automatizadas equivalentes están en `PermisosTests` (14 pruebas, ver [HU-05/pruebas.md](../HU-05/pruebas.md)).

## Resultado

| # | Caso | Esperado | Obtenido |
|---|---|---|---|
| 1 | Login de doc01 con credenciales válidas | 200 | 200 ✅ |
| 2 | Login con contraseña incorrecta | 401 | 401 ✅ |
| 3 | GET /api/cursos sin token | 401 | 401 ✅ |
| 4 | doc01 pide un curso ajeno (BDD-4B, id 2, asignado a doc02) | 403 | 403 ✅ |
| 5 | doc01 pide su curso (AGIL-4B, id 1) | 200 | 200 ✅ |
| 6 | doc01 lista sus cursos | 200 | 200 ✅ |

El token del caso 1 vence a las 16:01, 120 minutos después del login (`Jwt__ExpiraMinutos=120`).

## 1. Login de doc01 con credenciales válidas

```
POST /api/auth/login  (sin Authorization)
{
  "usuario": "doc01",
  "contrasena": "••••(contraseña de semillas)"
}
```

Respuesta **HTTP 200**:

```json
{
  "token": "••••0fCA",
  "expiraEn": "2026-10-22T16:01:51.9353021-05:00",
  "usuario": {
    "id": 2,
    "usuario": "doc01",
    "nombre": "Docente Uno",
    "rol": "DOCENTE"
  }
}
```

## 2. Login con contraseña incorrecta

```
POST /api/auth/login  (sin Authorization)
{
  "usuario": "doc01",
  "contrasena": "contrasena-incorrecta"
}
```

Respuesta **HTTP 401**:

```json
{
  "type": "https://httpstatuses.io/401",
  "title": "Credenciales incorrectas",
  "status": 401,
  "detail": "El usuario o la contraseña no son válidos."
}
```

## 3. GET /api/cursos sin token

```
GET /api/cursos  (sin Authorization)
```

Respuesta **HTTP 401**:

```json
{
  "type": "https://httpstatuses.io/401",
  "title": "No autenticado",
  "status": 401,
  "detail": "Falta el token, venció o no es válido."
}
```
